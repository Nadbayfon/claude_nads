# Internationalisation

## Locale rules

| Audience | Locale | Lives in |
|---|---|---|
| Planner UI | `en` | `apps/web/locales/en.json` |
| Couple-facing output (briefs, weekly status, contracts) | `en` | feature agents |
| Provider-facing output (RFQs, follow-ups, contracts ES half) | `ca` (default) or `es` | feature agents |
| Internal docs / `docs/*.md` | `en` | this folder |
| Source prompts | `en` (instructions to the model) | `prompts/` |

## Per-provider language

`provider.languages[]` carries the languages a provider speaks. RFQ
generation uses:

1. Catalan if the provider speaks `ca` (default for Catalonia).
2. Spanish if the provider speaks `es` but not `ca`.
3. English only if the provider speaks neither (rare — flag for review).

## CI lint (`crystal-i18n` skill)

- Couple-facing strings detected by file path glob:
  `apps/web/server/ai/(couple-intake|initial-proposal|weekly-status-email|translate-proposal).ts`
  and any output rendered in components under `apps/web/app/couple/*`.
  Must validate as English (basic dictionary heuristic).
- Provider-facing strings detected:
  `apps/web/server/ai/(translate-brief|provider-followup).ts`. Must
  validate as Catalan or Spanish.
- Workspace UI strings: must come from `locales/*.json`, not literals.
  ESLint rule `crystal/no-bare-strings` enforces.

## Catalan / Spanish quality

- LanguageTool runs on outbound CA/ES content from Phase 6 in CI.
- Glossary lives at `packages/ai/src/glossary.ts`:
  - `wedding planner` → `wedding planner` (stays English in
    Catalan trade jargon)
  - `welcome dinner` → `sopar de benvinguda` (CA) / `cena de bienvenida` (ES)
  - `provider proposal` → `pressupost del proveïdor` (CA) /
    `presupuesto del proveedor` (ES)
  - `payment milestone` → `fita de pagament` (CA) / `hito de pago` (ES)
  - `VAT` → `IVA` in both
- AI is told (in `translate-brief.md`) never to translate brand names,
  venue names, or proper nouns.

## Date and number formatting

- Display: `Europe/Madrid` time zone, 24h clock, `DD/MM/YYYY` for the
  workspace UI; long-form (`5 de juny de 2026`) for couple-facing
  documents.
- Money: thousand separator `.`, decimal `,` for CA/ES outputs; reverse
  for EN. `numeral` config in `packages/ui/src/format.ts`.
- Phone: stored as E.164; displayed in the locale's preferred format.

## Catalan vs Spanish — how the AI decides

Default Catalan for Catalonia. Use Spanish only when:

- Provider's only listed language is `es`.
- Couple explicitly requests Spanish documents (some Latin American
  couples).
- Document is bilingual contract — Spanish half is statutory.

The model must not produce Castilian Spanish when the provider has `ca`
in their languages list, even if Spanish is "easier" for it. This is a
trust signal with Catalan providers.
